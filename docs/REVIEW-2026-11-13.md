# Blue Dragon review — 13 November 2026

Reviewed main commit 0a96448f4d9effae0e634ae0be39143004e4737b (0.5.0 alpha). Source review; the user's exact installation warning and physical-device logs were not supplied. This is a focused release-readiness review, not a comprehensive security audit.

## Installation

Confirmed: the publisher distributes a Debug APK when private signing secrets are missing. Separate CI debug keys can prevent updates of the same package. Version 0.5.1 removes that fallback, requires all signing settings and checks the certificate and non-debuggable manifest. CI installs a release with a disposable test key and updates it in place using the same key. Test keys/APKs are not distributed.

Still required: owner-controlled long-lived release key and four private Actions secrets. The connector cannot provision Actions secrets. The configuration script can create/reuse an owner-held key and upload secrets through an authenticated GitHub CLI in the owner's trusted environment. It has static checks only; no account secrets were created during this review.

Warning diagnosis remains conditional:
- Update rejection: compare certificate and version code; also check storage, SDK compatibility and installer logs.
- Scan recommended / unknown app: Google's unknown-app scanning. Release signing cannot guarantee removal.
- Harmful classification or developer-verification requirement: inspect the exact warning and use Google's official resolution path.
- Allow from this source: Android's installer permission for the browser/files app, separate from app signing.

The reviewed manifest requests Internet and optional Termux RUN_COMMAND, with no SMS, contacts, call-log, accessibility, device-admin or overlay permission. This is not a Play Protect clearance.

## Fixes
- Installation info: version/code, debug status, public certificate SHA-256, Android API, WebView provider and installer.
- Clearing browser data clears retained copyable console results and invalidates pending old evaluations.
- Closed/destroyed tabs ignore pending evaluation results.
- Active WebView pauses/resumes with the Activity; this is not full background process suspension.
- Correct product-name text in browser menu and Termux setup.

## Road to wider distribution

| Priority | Work | Current limit / acceptance check |
|---|---|---|
| P0 | Configure stable production signing | Verify fresh install and update with the production key; publish fingerprint and keep offline backup. |
| P0 | Resolve exact installer warning | Capture complete text and version; no claim that warnings are removed yet. |
| P1 | HTTP cancel and overall deadline | One executor and read/connect timeouts can leave the UI waiting for a slow response. Add cancel/disconnect and a wall-clock deadline. |
| P1 | Opt-in session recovery | Tabs/UI state are memory-only. Restore URL snapshots after process death without automatically storing request secrets/output. |
| P1 | Network capture coverage | WebView exposes metadata, not full response bodies/statuses, POST bodies, all worker traffic or WebSocket frames. Design/test coverage before claiming full DevTools. |
| P1 | Terminal environment | Android pipe shell has no PTY/Linux packages. Verify separate Termux integration on physical devices and under permission/battery restrictions. |
| P1 | Device coverage | Android 15 emulator is a baseline. Test Android 8/10/13/15, low memory, small screens, keyboard resize and landscape. |
| P2 | Maintainability | MainActivity is roughly 900 lines; extract tab management, screens and task lifecycle. |
| P2 | Accessibility and Arabic | Localize strings, test TalkBack, large text and focus order; code/URLs remain LTR. Current Arabic test checks direction only. |
